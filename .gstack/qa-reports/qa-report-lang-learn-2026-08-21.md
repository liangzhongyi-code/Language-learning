## 問題明細

### ISSUE-001 — 測驗頁「下一題」落在視窗外

- **嚴重度**：medium
- **類別**：UX
- **狀態**：✅ verified
- **commit**：`f4e8580`
- **檔案**：`assets/js/ui/quiz-view.js`

**重現**：1280×720 視窗開 `en/quiz.html` → 開始測驗 → 點任一選項。

**實際 vs 應有**：

| 元素 | 底部位置 | 視窗高 |
|---|---|---|
| 選項區 | 698px | 720px |
| 回饋文字 | 766px | 720px |
| **下一題按鈕** | **751px** | **720px** |

即使把語音降級提示移除（模擬有語音包的真實瀏覽器），下一題底部仍在 751px。
**每答一題都要手動捲動才能繼續，一局 10 題就是 10 次。** 句子題的選項更長，落差更大。

**修法**：作答後 `scrollIntoView({ block: 'nearest', behavior: 'smooth' })`。
`nearest` 只在真的看不到時才捲，大螢幕完全不受影響。

**驗證**：作答後自動捲動 110px，按鈕底部落在 720px，完整進入視窗。

### ISSUE-002 — 國旗 emoji 在 Windows 渲染成 "GB" / "JP"

- **嚴重度**：medium
- **類別**：視覺
- **狀態**：✅ verified
- **commit**：`e368a68`
- **檔案**：`index.html`、`ja/index.html`、`assets/css/theme.css`

**重現**：Windows 上開首頁。

**實際 vs 應有**：兩張語言入口卡的 🇬🇧 / 🇯🇵 顯示成裸的 **"GB"** 與 **"JP"** 兩個字母。
Windows 從來沒有 regional indicator 的字型，所有版本都一樣——這不是設定問題，是平台限制。

順帶發現：`ja/index.html` 的 🈁 與 📇 渲染成單色輪廓，而同一排的 🧩 🎯 是彩色的。
Windows 在 Segoe UI Symbol 與 Segoe UI Emoji 之間各自 fallback，同一排卡片混搭。

**修法**：
1. 語言卡改用該語言的文字本身（英文 `Aa`、日文 `あ`），任何平台都顯示得出來，語意也更貼切
2. `.entry .icon` 明確指定 emoji 字型鏈，消除彩色／單色混搭

### ISSUE-003 — 教學頁對連接線開關的位置描述錯誤

- **嚴重度**：low
- **類別**：內容
- **狀態**：✅ verified
- **commit**：`ea3a4b3`
- **檔案**：`help.html`

**實際 vs 應有**：教學寫「文法頁右上角可以關掉它」，但實測開關在 `left: 220px`（1280px 視窗），
位於句型篩選列下方的**左側**。使用者照著找會找不到。

### ISSUE-004 — 本機 serve 的 clean-URL 讓相對連結 404

- **嚴重度**：medium
- **類別**：功能（僅本機開發）
- **狀態**：✅ verified
- **commit**：`3d06d9d`
- **檔案**：`serve.json`（新增）、`README.md`

**重現**：照 README 跑 `npx -y serve .` → 開首頁 → 點「英文」→ 點「字母發音」。

**實際 vs 應有**：`serve` 把 `/en/index.html` 轉址成 `/en`（**沒有結尾斜線**），
於是頁面裡的 `./alphabet.html` 解析成 `/alphabet.html` → 404。

```
實際網址:      http://localhost:9240/en
./alphabet.html 解析後: http://localhost:9240/alphabet.html   ← 錯
```

**線上不受影響**：GitHub Pages 直接服務 `.html` 回 200 不轉址，裸目錄則補上結尾斜線，
兩種情況相對路徑都正確。但 README 叫使用者跑的正是 `npx serve .`，照做就會踩到。

**修法**：新增 `serve.json` 關掉 `cleanUrls`，README 註明不要刪它。

**驗證**：網址維持 `/en/index.html`，連結解析為 `/en/alphabet.html`，點進去 26 張字母卡正常。

## 延後項目

### 假名卡的例字朗讀鍵無法用鍵盤操作

- **嚴重度**：medium
- **類別**：無障礙
- **狀態**：deferred（Phase 5 審查已知項）

`.kana` 本身是 `<button>`，內層不能再放可聚焦元素（巢狀互動元素是無效 HTML），
所以例字喇叭用 `<span>` 且沒有 `role="button"` / `tabindex`。
鍵盤使用者可以 Tab 到卡片按 Enter 唸字母，但唸不到 26 個例字。

修它要把 `.kana` 從 `button` 改成 `div` + `role="button"` + keydown 處理，
會動到既有的 CSS 與結構約定。列為後續 TODO，不在本次 QA 範圍。
