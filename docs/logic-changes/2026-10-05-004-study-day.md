## 需求與原因

每日額度不能因 OS 時區更動、切換級別或時鐘倒退重新取得。需要可注入時間、可保存固定時區、可獨立測試的純核心，供後續 daily-plan／repository 使用。首次使用者時區由 UI 提供。

## 純函數 exports 與契約

| Export | 輸入 | 回傳 |
|---|---|---|
| localStudyDate(now, timeZone) | 有限且可表示的 epoch 毫秒數、明確 IANA 名称 | YYYY-MM-DD |
| studyDayKey(localDate, lang) | 有效公曆日期、語言識別字 | `2026-10-05:ja` |
| studyPlanKey(localDate, lang, level) | 有效日期、語言、級別 | `2026-10-05:ja:N5` |
| createStudyDayState(timeZone) | UI 提供的首用時區 | `{ currentZone, pendingZone: null, latestDay: null }` |
| requestStudyTimeZone(state, timeZone) | 政策狀態、手動指定時區 | 新政策狀態；原物件不變 |
| resolveStudyDay(state, now) | 政策狀態、epoch 毫秒 | `{ localDate, timeZone, isNewDay, clockMovedBack, state }` |

```js
const initial = createStudyDayState('Asia/Taipei'); // UI 已取得／確認的值
const first = resolveStudyDay(initial, Date.parse('2026-10-05T00:00:00Z'));
const ledgerKey = studyDayKey(first.localDate, 'ja'); // 2026-10-05:ja
const planKey = studyPlanKey(first.localDate, 'ja', 'N5'); // 2026-10-05:ja:N5
// repository 將 first.state 與該日計畫、日帳本同交易保存。
const requested = requestStudyTimeZone(first.state, 'America/New_York');
const waiting = resolveStudyDay(requested, Date.parse('2026-10-05T16:00:00Z'));
// waiting.localDate = 2026-10-05，isNewDay=false；仍使用 Asia/Taipei。
const next = resolveStudyDay(waiting.state, Date.parse('2026-10-06T04:00:00Z'));
// next.localDate = 2026-10-06，timeZone=America/New_York，pendingZone=null。
```

## 規則、邊界與取捨

- core 不呼叫 Date.now、不讀 OS 預設時區、不碰 DOM／儲存／網路。固定 `gregory` 與 `latn`，不受預設 locale 影響。
- now 不接受 Date 物件或字串的隱式轉型；無限值、NaN、Date 無法表示的數值，以及結果年不在 0001–9999 者拋 RangeError。
- 缺省／空白／非法時區與數值 offset 拋 RangeError，不 fallback UTC 或 OS。
- 具名時區由 Intl 驗證執行環境支援性。單段名称另依 IANA 名單限制，避免 Intl 接受 PST、CST、ACT、AET 等非 IANA 名稱；保留 Japan、GMT、UTC 等合法別名。名稱依據：[IANA backward](https://data.iana.org/time-zones/tzdb/backward)、[IANA etcetera](https://data.iana.org/time-zones/tzdb/etcetera)。無新增執行期下載依賴。
- 日期依實際公曆驗證；鍵值組件只接受 `[A-Za-z0-9_-]+`，不能帶空白或冒號。語言與級別的業務白名單由上層管理。
- latestDay 是跨所有已建立日期的最大值，不是上次開頁時間。日期相等或倒退時沿用該日；不補發因往未來跳時跳過的中間日期。
- isNewDay 表示新日建立候選，**不是是否仍有新字餘額**。同日剩餘額度仍由 ledger 計算，不可只因 false 禁止所有新字。
- 手動改區後，必須目前區與待用區日期**都大於 latestDay**才採用 pending。向東不能當場取得新日；向西遇到已建日期會延後新日到待用區午夜，這是防止重領的保守取捨。等待時仍回傳既有日及 currentZone，不改寫其計畫。
- 重複手動選擇替換 pending；選回 currentZone（含 Intl 正規化後等價的別名）取消 pending。尚未建立首日時直接採用新區。
- clockMovedBack 只表示目前固定時區的日期小於 latestDay，不偵測同日秒數倒退。單機沒有可信伺服器時間，不能阻止刻意向未來調時，只能避免回退重領。
- 所有 state 轉換回傳新物件，失敗不覆寫輸入；缺欄位／壞日期不自動初始化，以免清掉 latestDay。state 有 currentZone、pendingZone、latestDay 三個必要欄位；無待改區／無已建日時必須明確 null。
- 跨頁競態、日帳本已存在檢查與 revision／epoch 仍是 repository 責任。純計算若不保存回傳 state，或只單獨保存而未原子建立計畫，不能保證防重領。
