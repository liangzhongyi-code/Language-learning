## 需求與原因

網站約定 ES2020，但 adapter／歷程頁使用數字分隔符、單字頁使用 nullish assignment，會在模組解析時失敗。成就的 Array.at 屬較新 API，僅做語法解析無法發現缺少 API 時的例外。這些路徑必須各自驗證。

## 變更前與變更後

| 情境 | 變更前 | 變更後 |
|---|---|---|
| ES2020 模組載入 | 三個模組使用 ES2021 語法 | 數值完全不變；空值預設使用 ES2020 的 `store = store ?? ...` |
| 日曆有學習紀錄但無 Array.at | 連續天數／成就計算拋例外，影響提交 | 排序後以陣列索引取末項；空日曆仍回 null |
| 相容性回歸 | 只解析 FSRS vendor | 遞迴解析 assets/js 與 app/prototype 全部 JS，另模擬缺少 Array.at |

## 規則、邊界與取捨

- 數值上限、提醒等待時間、空值注入、日曆排序及成就門檻都不改；不改排程演算法或持久資料。
- 新測試沿用 Node 內建 Acorn，不新增套件；解析器不存在時明確失敗，不以 skip 假通過。
- parser 自我測試證明會拒絕數字分隔符及邏輯指派；API 回歸涵蓋空／非空、亂序、雙語、零作答列與重算不重複解鎖。
- `tests/browser/suites/review-session-start.mjs` 在隔離 Chromium 移除 Array.at 後走真實自由測驗／練習提交及 IndexedDB 交易。不是舊版瀏覽器／真機矩陣認證。
- 不修改 Singer 的 web-repository 相容性修復，也不改 James 的 practice-view。
