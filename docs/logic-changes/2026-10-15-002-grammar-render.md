## 需求與原因

文法頁一次列出全部句子（日文 147 張卡）。載入時 `drawLinks` 為每張卡的每個色塊呼叫 `getBoundingClientRect` 與 `getComputedStyle`，逼瀏覽器當場把整份清單排版完；畫面只看得到兩三張卡，其餘工作都是白做。CPU 剖析顯示主執行緒幾乎都耗在這個迴圈。

## 變更前與變更後

| 情境 | 變更前 | 變更後 |
|---|---|---|
| 載入時畫連接線 | 147 張卡全部量座標、全部畫 | 只畫畫面附近（上下 300px）的卡片；其餘捲到時才畫 |
| 改寬度、字型載入、開關連接線 | 全部重畫 | 只重畫看得到的卡片，其餘標成過期，捲到時以新版面重畫 |
| 畫面外卡片的排版／繪製 | 每次都算 | `content-visibility: auto`，瀏覽器略過畫面外的卡片 |
| 線的顏色 | 逐塊 `getComputedStyle` 讀色後寫進 `stroke` | 線帶色塊的角色 class，CSS 以 `var(--blk)` 上色；切換外觀配色時線色會跟著變（原本維持舊色） |
| 教學頁示範句 | 同上，讀色寫入 | 同文法頁改用角色 class（CSS 共用，不改會變成單一顏色） |

## 規則、邊界與取捨

- `createLinkPainter()`：`IntersectionObserver` 追蹤畫面附近的卡片；每次版面變動遞增世代，卡片畫線時記下世代，過期者進入畫面才重畫。沒有 `IntersectionObserver` 的舊瀏覽器退回全部重畫（原行為）。
- 量測與寫入仍分兩階段（先量完這批再動 DOM）；卡片沒有版面時不記為已畫，下次進入畫面再試。
- `contain-intrinsic-size: auto 480px`：未顯示過的卡片以 480px 預估（實測中位數桌面約 440、手機寬度約 550），顯示過後記住實際高度。刻意不依寬度換預估值：測試時發現手機轉向跨過斷點，上百張未顯示卡片會一起變高約 15000px，捲動位置因此跑掉。
- 尋找頁面文字（Ctrl+F）與無障礙樹仍包含畫面外的卡片（`content-visibility: auto` 的既定行為）；不支援的瀏覽器只是不略過排版，畫線仍按需。
- 量測方法更正：先前紀錄引用的「長任務」數字（約 200～290ms）來自 Long Tasks API 與自製每影格 `innerText` 取樣，後者本身會強制排版而放大數字，前者則不含渲染。本次改用 Long Animation Frames（含樣式、排版、繪製，且不加任何量測負擔）作為前後比較依據。
