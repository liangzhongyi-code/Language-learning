## 需求與原因

線上（GitHub Pages）每點一次上方 TAB 都要等 1～4.5 秒才出現內容。原因不是頁面運算，而是 ES 模組「一層一層」下載：每頁 HTML 只寫了 `page-boot.js`，瀏覽器要等它下載、解析完才知道下一層要抓什麼，首頁的相依鏈深達 13 層（`today-card` → `daily-service` → … → `ts-fsrs`），每層都是一次網路往返。GitHub Pages 的快取只有 `max-age=600`，十分鐘後每層又要重新確認一次，所以常常「又卡了」。

實測（線上、首次載入）：首頁 50 個資源的請求從 468ms 一路排到 2575ms，內容完成約 4.5 秒；今日頁 1.6 秒、單字／文法頁約 1.5 秒。本機伺服器因往返幾乎為零，所以本機不明顯。

## 變更前與變更後

| 情境 | 變更前 | 變更後 |
|---|---|---|
| 頁面 `<head>` | 只有主題與樣式 | 另列該頁啟動會用到的全部程式模組 `<link rel="modulepreload">`（由工具產生） |
| 模組下載 | 逐層發現、逐層等待（首頁 13 層） | 讀完 HTML 就一次平行下載，剩約一次往返 |
| 題庫資料 | 依選擇按需載入 | 不變：分級單字、句型等題庫及今日頁的練習題仍按需載入，不預載 |

## 規則、邊界與取捨

- `tools/build-preload.mjs` 從每頁的模組 script（含 help／guide 的內嵌 import）出發，加上 `page-boot.js` 依 `data-page` 動態載入的模組（工具內 `bootModules` 對照表），取靜態 import 的封閉集合，寫入頁面帶標記的區塊；`--check` 只核對。
- 只預載「這頁一定會用到」的模組：不預載依使用者級別或題型才載入的資料，避免多抓流量，也維持既有「首頁只抓目前級別、歷程頁不抓題庫」的行為。
- 預載失敗等同原本 import 失敗：頁面仍顯示既有的「重新載入資料」提示，不影響導覽。
- 為什麼不打包成單一檔：網站維持零建置、零執行期相依，APP 也直接打包同一批檔案；modulepreload 不改任何程式碼路徑。
- 為什麼不改快取：GitHub Pages 無法自訂 Cache-Control；預載讓「快取過期後重新確認」也同樣平行化。
- `page-boot.js` 新增或改動動態載入的模組時，要同步更新 `bootModules` 並執行 `npm run build:preload`；瀏覽器測試 `module-preload` 會逐頁比對，漏列或多列都會失敗。
