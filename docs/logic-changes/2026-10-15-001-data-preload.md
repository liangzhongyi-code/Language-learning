## 需求與原因

前次把程式模組改成一次平行下載後，題庫仍要等 `page-boot.js` 執行完才知道抓哪一份，比程式晚一次網路往返。線上首頁在 DCL（1939ms）後才開始抓 `ja-words-1.js`，再過約 315ms 才完成。

## 變更前與變更後

| 情境 | 變更前 | 變更後 |
|---|---|---|
| 單字、單字簿頁 | 程式到齊後才抓五級單字 | HTML 直接列出五級單字 `<link rel="modulepreload">`，與程式同時下載 |
| 文法頁 | 程式到齊後才抓句型 | HTML 直接列出句型題庫 |
| 首頁、今日頁 | 程式到齊後才依已存今日級別抓該級單字 | 內嵌的小段腳本讀到 HTML 當下依同一偏好預載該級 |
| 測驗頁 | 程式到齊後才依網址題源抓題庫 | 內嵌腳本依 `?source=` 預載（規則同 quiz-view：英文沒有情境題時為單字、無效題源為單字） |
| 預載區塊位置 | `theme.css` 之後 | `<head>` 最前面（theme-boot 之前） |

## 規則、邊界與取捨

- 判斷邏輯的原始檔是 `assets/js/ui/data-preload.js`；`tools/build-preload.mjs` 去掉檔頭說明後內嵌到首頁／今日／測驗頁，不以 `src` 載入。
- 為什麼內嵌：外部腳本本身要先下載一次，等於又多一次往返（實測同步外部腳本只省 20～100ms，`async` 會被瀏覽器降為低優先，晚到 page-boot 之後完全無效）。內嵌腳本放在 theme-boot 與樣式表之前，不必等任何下載就執行。
- APP 的 CSP 為 `script-src 'self'`，Tauri 建置時會替打包頁的內嵌腳本加上雜湊（help／guide 既有的內嵌模組亦同），安裝版 21 頁皆無 CSP 錯誤。
- 仍只預載「這次一定會讀」的那份：首頁只抓目前級別、歷程頁不抓題庫等既有行為不變；今日頁的練習題仍等做到練習才載入。
- 猜錯（例如規則漂移）只會多抓或少抓，頁面仍由 page-boot 正常載入；瀏覽器測試 `module-preload` 逐頁核對，並加測今日級別 3／5、測驗七種題源（含英文情境題、無效題源）兩種語言，預載與實際讀取不一致就失敗。
- 修改今日級別、測驗題源規則或 page-boot 的題庫讀法時，要同步改 `data-preload.js` 並執行 `npm run build:preload`。
