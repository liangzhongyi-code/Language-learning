## 如何留下一次變更

1. 複製 TEMPLATE.md 為當日下一個流水號檔案，填需求與變更前後，狀態先設「規劃中」或「實作中」。
2. 隨同該次實作更新規則、相關檔案與驗證結果。指令尚未執行就寫「未執行」，不要引用別次測試冒充。
3. 交付前更新本索引與狀態；如果日後有 commit／發布，再補真實參照及日期。本文檔規則不自行授權提交或部署。

## 狀態與歷史

- 規劃中：尚未寫入正式行為；另記核准狀態。
- 實作中：程式已變動，驗證尚未完整。
- 已驗證：列出本次實際完成的驗證及仍待驗項目，不等於發布。
- 已發布：有可追溯的發布／部署證據。
- 取消／被取代：保留原文，補上原因及後續紀錄。
- 已完成紀錄若有事實錯誤，追加日期與更正說明；不要把舊決策改得像從未發生。

## 留存範圍與注意事項

- 本目錄從本次開始，不宣稱過去每個 commit 都已補寫。較早歷史請看 Git 與 [初版歸檔](../../openspec/archive/init-lang-learn-site/design.md)；需要回補時，只以可查證資料撰寫並標「補記」。
- 原始 Markdown 放在專案；外部 HTML 與「規格原始檔快照」是閱讀／保存副本，不是後續修改來源。
- 原始文件隨相應程式變更納入版控；僅在工作區保存時仍可能是未追蹤檔案，須如實告知。
- 找不到規格連結時，先查是否已歸檔；修正相對連結，不為維持連結另複製過期設計。
